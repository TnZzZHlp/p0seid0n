## 目标

交付可发布到 npm 的 `p0seid0n` 命令，让使用者用 `init` 建立 `components.json`、用 `add` 把 registry item 及其依赖写入自己的项目。

## 范围

### 包含

- `packages/cli` 包（`name: p0seid0n`、`bin: p0seid0n`）
- `p0seid0n init`：交互式或参数化生成 `components.json`
- `p0seid0n add <items...>`：支持本 registry 名称、URL、本地文件路径三种来源
- 依赖图解析（跨 item 的 `registryDependencies` 递归）
- 别名与 `target` 落点解析，包管理器探测与依赖安装
- 发布配置与打包校验

### 排除

- `p0seid0n diff`、`p0seid0n update`、`p0seid0n remove`（组件是拷贝，更新语义需单独设计）
- Nuxt/Vite 项目专用初始化流程
- 交互式组件多选界面
- `add all`（见 Q01）

### 接口与数据

命令与参数：

```text
p0seid0n init [--yes] [--cwd <dir>]
  生成 components.json；已存在时不覆盖，提示 --force

p0seid0n add <item...> [--overwrite] [--no-install] [--cwd <dir>] [--registry <url>]
  item 可以是：
    button                                    本 registry
    https://<host>/r/button.json              直连 URL
    ./button.json                             本地文件
```

`components.json` 读取字段（v1 子集）：`style`、`tailwind.css`、`tailwind.cssVariables`、`aliases.components`、`aliases.ui`、`aliases.lib`、`aliases.utils`。缺 `components.json` 时 `add` 提示先执行 `init` 并以非零退出。

落点规则：

| `files[].type` | 落点 |
| --- | --- |
| `registry:ui` | `aliases.ui` |
| `registry:lib` | `aliases.lib` |
| `registry:component` | `aliases.components` |
| `registry:file`（带 `target`） | 项目根下的 `target` |

别名解析：读取项目 `tsconfig.json`（或 `jsconfig.json`）的 `compilerOptions.paths`，把 `@/*` 之类映射为真实目录；解析失败时退回把别名当相对项目根的路径并给出提示。

依赖图解析：`add button` 时先取 `button.json`，对其 `registryDependencies` 递归取 `r/{name}.json`，按拓扑序安装（被依赖者先写），同一 item 只装一次，检测环形依赖并报错。

依赖安装：收集所有 item 的 `dependencies` 去重后一次性安装；探测顺序为 `pnpm-lock.yaml` -> `package-lock.json` -> `yarn.lock` -> `bun.lockb`，都无时用 npm；`--no-install` 时只打印需要执行的命令。

错误行为：目标文件已存在且内容不同 -> 不覆盖，列出冲突路径并提示 `--overwrite`；任一步失败即非零退出，已写入的文件保留并打印已完成的 item 列表（不做回滚删除，避免误删用户文件）。

### 运行行为

- 不联网的路径（本地文件、`--registry` 指向本地目录）必须完整可用，以便 CI 与文档站自举
- 网络请求带超时（10s）与单次重试，失败时打印来源 URL
- 输出保持简洁：每个 item 一行，写入路径用相对项目根的路径
- 不使用 emoji，不使用彩色装饰性图标
